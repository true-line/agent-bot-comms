# Stage 2a B relay candidate

Source candidate for Platform Discussion #120. The Comms package and HQ release builders do not build, install, or launch this command. It has no sandbox installer and grants no qualification authority.

Build on Darwin with cgo enabled and a pinned Go/SDK toolchain.

```sh
CGO_ENABLED=1 go build -trimpath -o agent-comms-stage2a-bridge .
CGO_ENABLED=1 go test -race ./...
```

The measured command is the absolute installed binary followed by the literal arguments below, with an empty environment.

```text
--assignment-fd 3 --proof-fd 4 --status-fd 5
```

The fixed launch rule must run the executable under its provisioned B UID/GID and confined profile and pass private anonymous pipes. FD 3 is a bounded JSON assignment followed by EOF. The `assignment`, `selectors`, `endpoint` and `identity` structs in relay.go define the exact field names. The v2 assignment identifies all three accounts, the broker socket and its parent, the uncreated relay socket and its parent, exact plan digests, current HQ epoch, pre-bind expiration, pinned model, normalized request and header digests, client API key digest, HTTP host, and literal Messages query. On the relay socket identity use zero device and inode, with the intended owner, group and mode. Supply device and inode as unsigned JSON integers, preserving full integer precision across the sending implementation.

Only the authenticated fixed launcher may populate those descriptors. This executable relies on the launcher to authenticate the Machine-signed assignment, prove the installed artifact and profile, check endpoint ancestry and ACLs, apply exact socket confinement, restrict groups and inherited descriptors, and associate the process with the live reservation. The assignment crosses no runner-controlled socket. FD 4 is 32 raw proof-key bytes followed by EOF. Relay diagnostics do not print assignment or proof data.

The executable checks broker peer UID in the kernel, pins the broker identity, sends `bridge.bind.v2.challenge` and `bridge.bind.v2` over one Unix stream, then binds the Unix relay and writes one JSON object to FD 5 with `bind_receipt_sha256` and the actual `relay_socket` identity. Before bind, B derives a completion-only subkey as HMAC-SHA256 of its 32-byte FD 4 proof with ASCII `agent-bot-stage2a-b-completion-subkey-v1`, one NUL byte, and the literal validated `selectors.reservation_digest`. Bind still clears the raw FD 4 proof immediately. B keeps only the derived subkey until its single full-write completion MAC or process exit, then clears it. The launch supervisor must recheck that socket and resolve the digest against HQ's current B binding before Machine finalization and R startup. B does not start R. The source default-off HQ dispatch patch and Comms plugin gate are independent prerequisites. After owner approval a trusted HQ entry point must verify Machine finalization, apply the two transport gates, and install the one-use local provider authorizer.

Each accepted Unix stream must have the assigned R peer UID. A literal policy-limits GET is answered locally. A POST for the exact assigned Messages path has one bounded strict JSON body, pinned model, exact host, headers and query. The v2 relay recognizes the pinned stock Claude ACP v0.109.0 macOS first streaming request (nine top-level fields and one user message) and the earlier eleven-field, two-message shape. The relay refuses duplicate or unknown JSON fields and requires every nonvolatile body field to match the signed normalized request digest. It removes only `metadata.user_id` before the Go `encoding/json` compact, sorted-top-level-key digest; that field's nested account, device and session IDs are shape-checked and never forwarded. Version, beta and other nonvolatile headers are bound by the signed header digest. The client API key and session header are checked and discarded. The request uses `application/json` and a single canonical Content-Length.

The same bound broker stream receives at most one `bridge.relay.ingress.v1` call with exactly `{model,prompt_sha256,peer}`. Here `prompt_sha256` is the normalized full request digest, which HQ must match to its installed plan before obtaining Machine's one-use local provider response. The `peer` object contains exactly nine kernel-observed nonnegative safe integers: `uid`, `pid`, `pid_version`, `start_seconds`, `start_micros`, `parent_pid`, `parent_uid`, `parent_start_seconds`, and `parent_start_micros`. B reobserves the accepted Unix client and its parent before ingress and after ingress acceptance.

B prepares the complete HTTP 200 SSE wire in memory and holds it while sending one `bridge.relay.prewrite.v1` on the same broker connection. Its exact ten top-level fields are `selectors`, `bind_receipt_sha256`, `peer`, `peer_sha256`, `request_sha256`, `prompt_sha256`, `model`, `response_wire_sha256`, `response_wire_bytes`, and `http_status`. The wire digest, byte count and status describe the prepared bytes, not a claimed write. B waits for the paired live observation to return `{accepted:true,prewrite_receipt}` with a bare 64-hex one-use receipt, then reobserves the same kernel peer immediately before writing. A missing or changed peer, failed prewrite, stopped context or changed endpoint refuses the positive write.

Only after every prepared response byte is written does B compute a domain-separated HMAC with its completion subkey over ASCII `agent-bot-stage2a-b-completion-origin-v1`, one NUL byte, and JCS of the exact 13-field completion body. B then clears the subkey and sends one `bridge.relay.complete.v1` with the 13 fields plus bare 64-hex `completion_origin_mac`. Completion carries the same peer and canonical peer digest, prewrite receipt, normalized full-request digest, exact parsed user-text UTF-8 digest, actual response wire digest and byte count, HTTP status, and the exact RFC3339Nano write-time strings. Partial or failed writes emit no completion MAC or frame. The broker accepts completion only after the matching one-use ingress and prewrite on that live connection and HQ's positive completion acknowledgement. B does not require the one-shot client PID to remain live after the final SSE byte; endpoint and stop checks still apply. The synthetic `bridge.qualification.messages.v1` route is not used by the installed relay. Bind calls and HTTP reads have five-second deadlines. The relay allows twenty seconds each for the provider round trip, paired prewrite and completion and sets a fresh five-second write deadline for every response. Broker EOF, path replacement or provider refusal shuts the relay down. The executable only removes its own verified socket and reports uncertain cleanup to its supervisor.

This executable changes the earlier proposed Node/addon package to a single Go/cgo native artifact. They establish neither distinct-account host custody nor sandbox egress, signing, installed invocation or physical qualification.
